# 业务事件触发付费 PRD + 推流透明化机制

> 用途：把"硬推付费"改成"业务事件触发"+ 把"黑箱推流"改成"透明化机制"  
> 核心信条：**好的商业化是用户"被业务推着付费"，不是销售"逼着付费"**

---

# 第一部分：业务事件触发付费 PRD

## 1.1 设计原则（铁律 5 条）

| 铁律 | 说明 |
|---|---|
| 1. **必须是用户达成业务里程碑时触发** | 不是注册多少天 / 登录多少次 |
| 2. **必须有"看得见的痛"** | 比如功能限制、效率下降、错过机会 |
| 3. **必须有"立竿见影的解决"** | 升级后 1 天内必须看到改善 |
| 4. **必须给"3 选 1"决策**（不是"升级 vs 不升级"）| 给"小升级 / 大升级 / 暂时不升级"3 个选项 |
| 5. **必须可关闭** | 用户拒绝 3 次 → 暂停推送 30 天 |

## 1.3 触发频次控制

| 用户行为 | 触发动作 |
|---|---|
| 第 1 次拒绝 | 30 天内不再弹同主题 |
| 第 2 次拒绝 | 60 天内不再弹同主题 |
| 第 3 次拒绝 | **永久不弹** + 顾问关注 |

## 1.4 数据埋点

每个触发事件必须记录：
- 触发场景
- 触发时间
- 用户当时业务数据
- 用户响应（升级 / 试用 / 拒绝 / 关闭）
- 后续转化情况

每月做 1 次"触发事件转化漏斗复盘"。

# 第二部分：推流透明化机制

## 2.1 为什么必须透明化

> **找钢网 2014-2016 推流不透明 → 卖家投诉 → 监管介入 → 估值跌 30%**

钢贸圈最在意的就是"公平"——平台一旦被怀疑"按关系推流"，公信力立刻崩。

## 2.2 推流的"3 维度评分"

```
最终排序权重 = 信用评分（55%）+ 活跃度（30%）+ 资质（15%）
```

### 维度 1：信用评分（55%）
详见 docs/30 信用评分模型

### 维度 2：活跃度（30%）
- 最近 30 天登录次数
- 最近 30 天报价次数
- 最近 30 天响应询价的速度
- 最近 30 天主动更新库存频次

### 维度 3：资质（15%）
- 营业执照 + 税务登记 + 行业许可
- 注册资本
- 经营年限
- 历史案件 / 失信记录

## 2.3 透明化「3 个让卖家看得见」

### 1. 看得见自己的"分数"
卖家后台首页直接显示：
```
─────────────────────────────────
  您的综合排序权重：78 / 100
─────────────────────────────────
  信用评分：72 / 100（排名 35%）
  活跃度：85 / 100（排名 15%）⭐
  资质：80 / 100（排名 25%）
─────────────────────────────────
  排名提升建议：
  ✓ 完成 1 笔订单按时发货 → 信用 +5
  ✓ 启用对账通 → 信用 +3
  ✓ 7 天内更新库存 → 活跃度 +5
─────────────────────────────────
```

### 2. 看得见"为什么没被推荐"
当卖家询问为什么未在某次匹配中被推荐：
```
─────────────────────────────────
  本次询价：买家 XX 钢厂
  品类：Φ60 焊管，500 吨
  
  您未被推荐，原因：
  ✗ 您的库存仅 200 吨（< 500 吨需求）
  ✓ 价格符合
  ✓ 信用符合
  ✓ 物流符合
  
  建议：更新库存数据 / 调整最小起订量
─────────────────────────────────
```

### 3. 看得见"推流的算法规则"
平台公开算法白皮书：
- 权重分配
- 计算公式
- 防作弊规则
- 申诉机制

## 2.4 推流权重的"分阶段调整"

| 阶段 | 信用 | 活跃度 | 资质 | 说明 |
|---|---|---|---|---|
| M1-M6 | 25% | 50% | 25% | 鼓励大家用 |
| M7-M12 | 40% | 35% | 25% | 信用数据初步沉淀 |
| M13-M18 | 50% | 30% | 20% | 信用为主 |
| M19+ | 55% | 30% | 15% | **稳态** |

## 2.5 反作弊机制

### 防刷活跃度
- 每天登录上限：5 次（超过不加分）
- 每天更新库存上限：3 次
- 同 IP / 同设备 / 同账号关联检测

### 防刷信用评分
- 自营订单**不计入**信用评分
- 关联账号识别（公司股权 / 注册地 / IP）
- 异常订单审计（大额 / 频繁 / 金额过整）

### 防刷资质
- 企业资质 OCR + 工商系统对比
- 注册资本 ≠ 实缴资本（明确区分）

## 2.6 申诉机制

### 5 级申诉
1. **自助查询**：后台直接看排名原因
2. **AI 答疑**：大语言模型自动回复
3. **平台顾问**：1 对 1 答疑（24 小时内）
4. **业务总监**：复杂申诉（48 小时内）
5. **第三方仲裁**：协会 / 律所介入（极端情况）

# 第四部分：5 个常见问题

## Q1：业务事件触发会不会让用户烦？
**A**：
- 关键是"频次控制"：拒绝后 30/60 天不再弹
- 关键是"价值清晰"：必须显示"预期效果"
- 关键是"可关闭"：永远给"不感兴趣"按钮

## Q2：推流透明化会让卖家"刷分"吗？
**A**：
- 会。所以必须配套"反作弊"
- 但即便刷分，也只是把"消极用户"变成"积极用户"——平台获利
- 真正的恶意刷分（虚假交易 / 关联账号）必须严打

## Q3：信用评分公布了，低分卖家会闹吗？
**A**：
- 早期会
- 关键是"指引清晰"——告诉他怎么提分
- 关键是"申诉通畅"——24-48 小时回复
- 关键是"权重分阶段"——M1-M6 信用占比小，给低分卖家时间提升

## Q4：业务事件触发的开发成本多少？
**A**：
- 8 个触发场景 + 推流透明化 ≈ 200-300 人天
- 折算 ¥30-50 万开发成本
- M3 上 P0 的 3 个，M5 上 P1 的 3 个，M9-M12 上 P2

## Q5：触发付费会被监管认定为"诱导消费"吗？
**A**：
- 不会，只要：
  - 价格清晰
  - 价值清晰
  - 用户可拒绝
  - 不滥用提醒

# 5 句话总结

1. **业务事件触发付费 = 用业务结果说话**，转化率从 5-8% 拉到 25-35%
2. **8 个触发场景按 P0/P1/P2 分阶段上线**，不要一次全做
3. **推流透明化是平台公信力的命门**——找钢网踩过的坑不能再踩
4. **信用 + 活跃度 + 资质 三维评分 + 分阶段调权重**
5. **反作弊 + 申诉机制必须配套**——否则透明化会被滥用
