### 1.1 评分公式
```
信用评分 = Σ (维度得分 × 维度权重)
       范围：0-100
       分级：S(≥90) / A(80-89) / B(70-79) / C(60-69) / D(<60)
```

## 第二章：10 维度详细评分规则

### 维度 1：履约率（20 分）

```
履约率 = 按时发货订单数 / 总订单数
```

| 履约率 | 得分 |
|---|---|
| ≥ 99% | 20 |
| 95-98% | 16-19 |
| 90-94% | 12-15 |
| 85-89% | 8-11 |
| < 85% | 0-7 |

**说明**：
- 仅统计平台内成交订单
- 「按时」= 合同约定发货日 ± 1 天
- 自营订单**不计入**（避免左手买右手）

### 维度 2：对账及时（12 分）

```
对账及时率 = 30 天内对账完成订单数 / 总成交订单数
```

| 对账及时率 | 得分 |
|---|---|
| ≥ 95% | 12 |
| 85-94% | 9-11 |
| 70-84% | 5-8 |
| 50-69% | 2-4 |
| < 50% | 0-1 |

**说明**：
- 统计平台对账通的对账记录
- 鼓励卖家+买家用对账通（提高活跃度）

### 维度 3：客户投诉率（10 分）

```
投诉率 = 客户投诉数 / 总成交订单数
```

| 投诉率 | 得分 |
|---|---|
| 0% | 10 |
| < 0.5% | 8-9 |
| 0.5-1% | 5-7 |
| 1-2% | 2-4 |
| > 2% | 0-1 |

**说明**：
- 投诉必须经平台审核确认
- 误判 / 恶意投诉不计入

### 维度 4：平台月活度（8 分）

```
活跃度 = 月登录天数 + 月报价次数 / 行业平均
```

| 月活情况 | 得分 |
|---|---|
| 每周登录 + 月报价 ≥ 30 次 | 8 |
| 每两周登录 + 月报价 15-29 次 | 5-7 |
| 月登录 1-2 次 + 月报价 5-14 次 | 2-4 |
| 月几乎不登录 | 0-1 |

### 维度 5：经营年限（6 分）

| 经营年限 | 得分 |
|---|---|
| ≥ 10 年 | 6 |
| 5-9 年 | 4-5 |
| 3-4 年 | 2-3 |
| 1-2 年 | 1 |
| < 1 年 | 0 |

### 维度 6：注册资本（6 分）

| 注册资本（万元）| 得分 |
|---|---|
| ≥ 5,000 | 6 |
| 1,000-5,000 | 4-5 |
| 500-1,000 | 2-3 |
| 100-500 | 1 |
| < 100 | 0 |

**说明**：注册资本 ≠ 实缴资本，公开信息查 + OCR 验证

### 维度 7：合同纠纷历史（10 分）

```
基于中国裁判文书网公开数据
```

| 5 年内涉诉 | 得分 |
|---|---|
| 0 件 | 10 |
| 1-2 件（小额）| 7-9 |
| 3-5 件 | 3-6 |
| > 5 件或大额 | 0-2 |

### 维度 8：法定代表人征信（10 分）

```
基于个人征信报告（用户授权）
```

| 征信情况 | 得分 |
|---|---|
| 无失信 + 无逾期 | 10 |
| 无失信 + 历史轻度逾期 | 7-9 |
| 历史失信已结 | 3-6 |
| 当前失信 | 0 |

**说明**：
- 用户必须**主动授权**才查
- 不授权不强制（但 -3 分）

### 维度 9：数据完备度（8 分）

```
完备度 = 已填字段 / 应填字段
```

字段包括：
- 营业执照
- 税务登记
- 银行账户
- 法人身份证
- 企业实景照
- 仓储 / 厂区照
- 主营品类
- 服务区域

| 完备度 | 得分 |
|---|---|
| ≥ 95% | 8 |
| 80-94% | 6-7 |
| 60-79% | 4-5 |
| < 60% | 0-3 |

### 维度 10：同行评价（10 分）

```
评价分 = (五星数 × 5 + 四星数 × 4 + ...) / 总评价数
```

| 平均分 | 得分 |
|---|---|
| ≥ 4.8 | 10 |
| 4.5-4.7 | 8-9 |
| 4.0-4.4 | 5-7 |
| 3.5-3.9 | 2-4 |
| < 3.5 | 0-1 |

**说明**：
- 必须是平台内**真实成交**的买家给评价
- 评价数 < 5 → 不计入此维度（按平均分代）

## 第四章：信用评分的"3 个反作弊"

### 反作弊 1：关联账号识别
- 同股权 / 同地址 / 同 IP / 同设备 → 关联账号
- 关联账号之间的交易**不计入信用**
- 关联账号互评 → 不计入"同行评价"

### 反作弊 2：异常订单审计
- 大额订单（> ¥100 万）+ 无物流凭证 → 标记
- 频繁订单（> 10 单/日）+ 同一买家 → 标记
- 金额过整（如 ¥500,000）+ 无加工细节 → 标记
- 标记的订单**人工审核**，确认刷单 → 信用 -20

### 反作弊 3：评价真实性
- 必须**真实成交 + 已对账完成 + 时间 > 7 天**才能评价
- 评价限定 1 次 / 1 笔订单
- 评价的 IP / 设备 / 时间异常 → 标记审核

## 第二章：算法架构（早期 → 成熟）

### 2.1 V1 算法（M1-M6）：规则匹配 + 人工辅助

```
[买家询价]
    ↓
[规则筛选] 
    - 品名牌号匹配
    - 规格匹配
    - 库存 ≥ 需求 80%
    - 物流距离 ≤ 800km
    ↓
[评分排序]
    评分 = 信用 × 0.3 + 价格 × 0.3 + 距离 × 0.2 + 历史 × 0.2
    ↓
[Top 5 推荐]
    ↓
[人工辅助]（平台顾问介入）
    - 买家不满意 → 顾问手动加 5-10 家进入
    - 标注好坏匹配 → 训练 V2
    ↓
[发送给买家]
```

### 2.2 V2 算法（M7-M18）：机器学习匹配

```
基于 V1 沉淀的 6 月数据 + 顾问标注
训练机器学习模型（推荐 XGBoost / LightGBM）

特征工程：
  - 品类匹配度（embedding）
  - 库存匹配度（数值）
  - 价格分（基于近 30 天市场价）
  - 物流综合分（距离 + 时效）
  - 信用分
  - 历史交易频率（买家-卖家）
  - 历史满意度
  - 实时活跃度

输出：每个候选卖家的"匹配概率"
```

### 2.3 V3 算法（M19+）：深度学习 + 多目标优化

```
深度学习模型（推荐 DLRM / Wide & Deep）

多目标：
  - 成交概率（最大化）
  - 平台 GMV（最大化）
  - 买家满意度（最大化）
  - 卖家收益均衡（防止头部垄断）

实时学习 + A/B 测试
```

## 第三章：早期 V1 算法详细规则

### 3.1 第 1 步：规则筛选（硬性）

```python
def filter_sellers(query, sellers):
    """硬性筛选"""
    filtered = []
    for seller in sellers:
        # 品名匹配
        if not match_product(query.product, seller.products):
            continue
        # 牌号匹配（允许同等级别替代）
        if not match_grade(query.grade, seller.grades):
            continue
        # 规格匹配（允许 ±2% 偏差）
        if not match_spec(query.spec, seller.specs, tolerance=0.02):
            continue
        # 库存量（≥ 需求 80%）
        if seller.stock < query.demand * 0.8:
            continue
        # 物流距离（≤ 800km）
        if distance(seller.location, query.location) > 800:
            continue
        # 卖家活跃（最近 7 天有登录）
        if seller.last_login > 7:
            continue
        filtered.append(seller)
    return filtered
```

### 3.2 第 2 步：评分排序

```python
def score_sellers(query, filtered_sellers):
    """评分"""
    scored = []
    for seller in filtered_sellers:
        # 信用分（30%）
        credit_score = seller.credit_score / 100  # 0-1
        
        # 价格分（30%）
        # 价格越接近市场均价，分越高
        market_avg = get_market_price(query)
        price_diff = abs(seller.last_price - market_avg) / market_avg
        price_score = max(0, 1 - price_diff * 2)
        
        # 距离分（20%）
        # 距离越近分越高
        dist = distance(seller.location, query.location)
        distance_score = max(0, 1 - dist / 800)
        
        # 历史关系分（20%）
        # 历史成交次数越多分越高
        history_count = get_history(query.buyer, seller)
        history_score = min(1, history_count / 10)
        
        total = (
            credit_score * 0.30 +
            price_score * 0.30 +
            distance_score * 0.20 +
            history_score * 0.20
        )
        scored.append((seller, total))
    
    return sorted(scored, key=lambda x: -x[1])
```

### 3.3 第 3 步：Top 5 推荐 + 人工兜底

```python
def recommend(query):
    sellers = get_all_sellers()
    filtered = filter_sellers(query, sellers)
    scored = score_sellers(query, filtered)
    
    top5 = scored[:5]
    
    # 如果筛选后 < 3 家 → 触发人工兜底
    if len(top5) < 3:
        notify_consultant(query, "候选不足，需人工介入")
    
    return top5
```

## 第四章：3 个早期算法的"补救机制"

### 补救 1：「公开求购」机制
- 当 AI 推荐失败（买家不满意）→ 触发"公开求购"
- 求购信息向**全平台符合品类的卖家**广播
- 卖家**主动报价**
- 平台撮合

### 补救 2：「平台顾问」介入
- 平台顾问在后台看每条询价
- 当顾问判断"AI 不准" → 手动添加 5-10 家进入推荐列表
- 标注 AI 的"漏报 / 错报"
- 数据用于 V2 训练

### 补救 3：「买家反馈」回路
- 买家收到推荐后必须 5 秒内反馈：
  - "不错，开始询价"
  - "不太对，再推荐"
  - "都不行，求购"
- 反馈数据**实时**用于 AI 训练

## 第五章：AI 算法的"4 个反偏见"

### 反偏见 1：防止头部卖家垄断
- 同一询价 → Top 5 中**至少 1 家"非头部"卖家**（信用评分 60-80）
- 给"潜力卖家"机会

### 反偏见 2：防止价格战
- 价格分**不是越低越好**
- 价格 < 市场均价 5% → 触发"价格异常"标记（可能是劣质货）
- 价格 > 市场均价 10% → 减分

### 反偏见 3：防止物流垄断
- 同区域多个卖家 → 不只推距离最近的
- 给次近卖家机会（避免某一区域被垄断）

### 反偏见 4：防止"老朋友锁单"
- 历史关系分**最高 20%**（不能太高）
- 否则买卖双方"绕开平台"在线下成交

# 总结：5 句话给老板

## 信用评分
1. **信用评分必须分阶段权重**——M1-M6 不能用"履约率"（没数据）
2. **信用数据外卖给银行 / 保理 / 大买家**——毛利 80%+，是 C 闭环最赚钱部分
3. **反作弊机制必须配套**——否则评分系统崩盘

## AI 询价
4. **早期不要追求"纯 AI"**——V1 规则 + 人工辅助是正解
5. **3 个补救机制**（公开求购 / 顾问介入 / 买家反馈）保证用户体验
