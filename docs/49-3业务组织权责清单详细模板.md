# 3 业务组织权责清单详细模板

> 用途：把 docs/45 组织设计 落地为可执行的"权责矩阵"  
> 解决：3 业务并行时"谁管什么、谁拍板、谁汇报"的全部争议

---

# 第一部分：3 业务权责的"5 大维度"

| 维度 | 说明 |
|---|---|
| **战略层** | 业务方向 / 客群 / 价格 / 边界 |
| **运营层** | 销售 / 营销 / CS / 产品 / 技术 |
| **职能层** | 财务 / HR / 法务 / IT 中台 |
| **协同层** | 跨业务客户 / 数据共享 / 联合销售 |
| **资源层** | 预算 / 招聘 / 工程优先级 |

| 决策项 | CEO | COO | 业务 1 VP | 业务 2 总裁 | 业务 3 VP | 董事会 |
|---|---|---|---|---|---|---|
| 公司战略方向 | A | C | C | C | C | I |
| 业务边界仲裁 | A | R | C | C | C | — |
| 客群定义 | C | A | R（业务 1）| R（业务 2）| R（业务 3）| — |
| 定价策略 | C | A | R | R | R | I |
| 跨业务客户归属 | A | R | C | C | C | — |
| 业务关停 / 新增 | A | C | C | C | C | C |
| 子公司化决策 | A | C | C | C | C | A |

**关键铁律**：
- 战略级**只有 CEO 是 A**（最终拍板）
- 业务 VP 在自己业务内是 R + A
- 跨业务的事 → COO 协调 → CEO 拍板

# 第四部分：决策时长 SLA（必须明确）

## 4.1 各级决策的"响应时间"

| 决策级别 | 响应时间 | 决策时间 |
|---|---|---|
| CEO 级（战略 / 跨业务 / 重大客户）| 24 小时 | 7 天内 |
| COO 级（运营 / 协同 / 资源）| 12 小时 | 3 天内 |
| 业务 VP 级（业务内）| 4 小时 | 1 天内 |
| 销售总监 / CS 总监 级 | 2 小时 | 半天内 |

## 4.2 紧急情况的「3 级升级」

| 等级 | 触发 | 上报 |
|---|---|---|
| 紧急 1（客户级）| 客户准备流失 | CS 总监 → 业务 VP |
| 紧急 2（业务级）| 月度营收 < 50% 目标 | 业务 VP → COO |
| 紧急 3（公司级）| 现金流告急 / 重大法律事件 | COO → CEO 立即上报 |

# 第五部分：跨业务协同的「冲突处理矩阵」

## 5.1 常见冲突 + 处理

| 冲突场景 | 处理 |
|---|---|
| 业务 1 想 / 业务 2 也想做同一客户 | COO 仲裁，按"首次接触 + 主营业务"分 |
| 工程师资源不够，业务 1 vs 业务 2 抢 | CEO 拍板优先级（基于战略） |
| 数据共享分歧 | CEO 拍板 + 用户授权 |
| 业务 VP 之间意见冲突 | COO 调解 → 不行就 CEO 拍 |
| 价格 / 提成方案分歧 | CFO + CEO 拍 |

## 5.2 协同会议机制

| 会议 | 频次 | 参加人 | 时长 |
|---|---|---|---|
| 业务 VP 周例会 | 每周一 09:00 | CEO + COO + 业务 VP | 60 分钟 |
| 协同月例会 | 每月底 | COO + 业务 VP + CFO + 中台 | 90 分钟 |
| 季度战略会 | 季度末 | CEO + 全管理层 | 半天 |
| 半年 OKR 对齐 | H1/H2 末 | 全公司 | 1 天 |
| 年度战略会 | 年底 | CEO + 全管理层 + 董事会 | 2 天 |

# 第七部分：权责清单的"3 个落地动作"

## 动作 1：全员公开
- 权责清单**全员可见**（飞书 / 钉钉）
- 每季度复审 1 次
- CEO 签字确认

## 动作 2：决策模板化
- 重大决策必须**填决策模板**（决策项 + RACI + 时间 SLA）
- 留痕 → 复盘

## 动作 3：周例会 RACI 跟踪
- 周例会每个 action item 必须标注 RACI
- 责任人不明 → 当场指定

---

# 第八部分：权责清单的"5 个铁律"

| 铁律 | 说明 |
|---|---|
| 1. 每件事必须有 1 个 A（拍板）| 没有 A = 没人决策 = 拖死 |
| 2. R 可以多个，A 只能 1 个 | A 多个 = 互推 |
| 3. C 不是"必须采纳" | 咨询不等于同意 |
| 4. I 不能少 | 知情权很重要 |
| 5. 升级机制必须清晰 | 当 R 和 A 冲突时谁决定 |

---

# 第九部分：5 句话给老板

1. **权责清单必须落到具体决策项**——不能只讲"谁管什么"
2. **A（拍板）只能 1 个人**——多个 A = 互相推卸
3. **跨业务协同必须有 COO**——CEO 一个人处理不来
4. **决策有 SLA 时间约束**——避免"等回复"拖延
5. **每季度复审 1 次**——业务演进了，权责也要演进

# 附录：3 阶段权责演进

## 阶段 1（M1-M6 25 人）
- CEO 直接管业务 VP
- 没有 COO
- 简化 RACI

## 阶段 2（M7-M18 70 人）
- COO 入职 → 接手日常运营
- CEO 退到"战略 + 关键客户"
- 完整 RACI 启用

## 阶段 3（M19+ 150 人）
- 业务子公司化 → 业务 VP 升"子公司 CEO"
- 集团总部成为"投资人 + 服务商"
- 矩阵式管理（业务 × 职能）
